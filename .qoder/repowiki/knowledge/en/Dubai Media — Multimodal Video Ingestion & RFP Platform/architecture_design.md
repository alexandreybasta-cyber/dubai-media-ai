Two-process monorepo orchestrated by `docker-compose.yml` (backend on :8000, frontend on :3000, nginx:alpine reverse proxy on :8080 sharing a named `uploads` volume). Nginx (`nginx.conf`) proxies `/api/*` to FastAPI, `/ws/*` with WebSocket upgrade, and serves `/uploads/` directly from the shared volume so media is accessible without hitting the Python process. Backend layering: `routers/` (HTTP/WebSocket entry points) → `services/` (RFP creation/evaluation orchestration) → `pipeline/` (sequential 6-stage `PipelineOrchestrator`: ingestion → visual analysis → audio transcription → face recognition → metadata structuring → FAISS search indexing), each stage persisted as `<stage>.json` plus a shared `status.json`. Configuration is centralized in `config.py` using `pydantic-settings.BaseSettings` with a model validator that falls back `DASHSCOPE_VIDEO_API_KEY` to the base key; env file path is hard-coded to `../.env` relative to `backend/`. Frontend (`frontend/src`) is a Next.js 16 app whose single source of truth for backend calls is `lib/api.ts`, which exports typed wrappers (`apiFetch`, `uploadFile` with XHR progress, `connectWebSocket`) and strongly-typed payload/result interfaces consumed by page components under `app/` and reusable UI under `components/`. Data plane is filesystem-first: UUID-named directories under `backend/uploads/<video_id>/` hold every artifact (`audio.wav`, `transcript.json`, `faces.json`, `visual_analysis.json`, `metadata.json`, `results.json`, `status.json`, optional `scenes/`); FAISS vectors live in `backend/data/search_index/`.
