- Two-process monorepo: `backend/` (FastAPI) serves REST + WebSocket endpoints under `/api/*`, mounts `/uploads` as static files, and delegates long-running work to a detached subprocess launched by `routers/video.py`'s upload handler (`subprocess.Popen(run_pipeline.py)`).
- Backend layering: `routers/` (HTTP/WebSocket entry points) → `services/` (RFP creation/evaluation orchestration) → `pipeline/` (sequential 6-stage `PipelineOrchestrator`: ingestion → visual analysis → audio transcription → face recognition → metadata structuring → FAISS search indexing), each stage persisted as `<stage>.json` plus a shared `status.json`.
- Configuration is centralized in `config.py` using `pydantic-settings.BaseSettings` with a model validator that falls back `DASHSCOPE_VIDEO_API_KEY` to the base key; env file path is hard-coded to `../.env` relative to `backend/`.
- Frontend (`frontend/src`) is a Next.js 16 app whose single source of truth for backend calls is `lib/api.ts`, which exports typed wrappers (`apiFetch`, `uploadFile` with XHR progress, `connectWebSocket`) and strongly-typed payload/result interfaces consumed by page components under `app/` and reusable UI under `components/`.
- Orchestration is Docker Compose-driven (`docker-compose.yml`): `backend` (uvicorn on 8000), `frontend` (Next dev on 3000), and an `nginx:alpine` reverse proxy on 8080 sharing a named `uploads` volume so Nginx can serve media while the backend writes it.
- Data plane is filesystem-first: UUID-named directories under `backend/uploads/<video_id>/` hold every artifact (`audio.wav`, `transcript.json`, `faces.json`, `visual_analysis.json`, `metadata.json`, `results.json`, `status.json`, optional `scenes/`); FAISS vectors live in `backend/data/search_index/`.
