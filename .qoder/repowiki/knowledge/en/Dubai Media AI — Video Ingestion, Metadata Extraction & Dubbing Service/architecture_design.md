Monolithic Python service organized in three layers under `backend/`:
- `main.py` bootstraps the FastAPI app (CORS, `/uploads` static mount) and includes two routers (`routers/video.py`, `routers/rfp.py`).
- `routers/` are HTTP/WebSocket entry points. `video.py` owns upload, status polling, metadata retrieval, transcript/subtitle/dubbing endpoints, search, reindex, and WebSocket progress; it never executes the pipeline itself — on upload it spawns a fully detached `subprocess.Popen` of `run_pipeline.py` so the event loop stays responsive.
- `services/` holds business logic: `rfp_creator.py` (RFPCreator class generating DOCX/PDF via python-docx/reportlab) and `rfp_evaluator.py` (vendor scoring).
- `pipeline/` is the processing core: `orchestrator.PipelineOrchestrator` drives a fixed sequence defined in `STAGE_NAMES` (`ingestion → visual_analysis → audio_analysis → face_recognition → metadata_structuring → search_index`) plus a non-blocking subtitle generation step. Each stage is an async coroutine in its own module (`pipeline/*.py`) returning a dict persisted as `<stage>.json`. A shared `status.json` tracks per-stage state (`pending|running|completed|failed`) with ISO timestamps.
- `data/search_index/` holds FAISS vectors (`faiss.index`) and segment metadata (`metadata.pkl`); `SearchIndex` wraps either FAISS or a pure-Numpy flat index depending on availability.
- Configuration is a single module-level singleton `settings = Settings()` from `config.py` using `pydantic-settings.BaseSettings` with `env_file="../.env"`; a model validator falls back `DASHSCOPE_VIDEO_API_KEY` to `DASHSCOPE_API_KEY`. All downstream modules import this instance rather than re-instantiating settings.
The repo root also contains a Next.js frontend (`frontend/src/app/...`) with pages for archive, RFP creator, and evaluator, plus `docker-compose.yml` wiring backend + frontend + nginx proxy and `nginx.conf` for reverse-proxied access to both services.
